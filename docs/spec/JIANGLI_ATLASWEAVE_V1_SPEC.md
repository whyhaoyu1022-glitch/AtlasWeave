1. 不得擅自删减本规格书中的“必须”功能。
2. 不得以占位按钮、无响应菜单、静态假数据代替真实实现。

5. 当两个条款看似冲突时，优先级依次为：
   - 数据不丢失与工程文件可恢复；

6. 每完成一个里程碑，必须运行对应的自动化测试和最小人工验收流程。
7. V1.0 应形成可安装、可启动、可创建、可保存、可再次打开、可导出的完整桌面应用，不是技术原型。

# 1. 产品定义

## 1.1 一句话定义

**疆理 AtlasWeave** 是一款让用户从空白画布开始，绘制虚构国土、建立多级行政区划、编辑共享边界、管理区域属性，并导出专业彩色行政地图的桌面创作工具。

## 1.2 核心价值

用户不需要掌握 GIS、拓扑学或专业制图软件，即可：

1. 创建一个虚构国家或世界的国土轮廓；
2. 像切蛋糕一样把领土切分为省、州、市、县等区域；
3. 让简单直线或规则曲线自动变成自然、不规则但可控的行政边界；
4. 为每个区域建立父子关系、名称、类型、首府、人口、GDP 等资料；
5. 自动检测重叠、缝隙、越界、无父级、名称冲突等问题；
6. 一键生成不同颜色、带标签和图例的行政区划地图；
7. 保存为可持续编辑的工程文件，并导出常见图片、矢量和地理数据格式。

## 1.3 V1.0 目标用户

| 用户类型 | 主要需求 |
|---|---|
| 小说与世界观创作者 | 为虚构国家建立稳定、可迭代的行政地图 |
| 桌游、跑团与战棋作者 | 快速划分领地、记录层级和属性 |
| 独立游戏开发者 | 创建区域数据并导出 SVG/GeoJSON/邻接信息 |
| 架空历史爱好者 | 设计国家、省州、市县及飞地 |
| 地图设计爱好者 | 获得比普通绘图软件更懂行政区划的编辑体验 |

## 1.4 V1.0 成功标准

一个从未接触过 GIS 的用户，应能在 15 分钟内完成以下完整流程：

1. 新建一个 1200 km × 800 km 的虚构国家工程；
2. 绘制一个闭合国土轮廓；
3. 新建“省级”层级；
4. 使用切分工具划出至少 6 个省；
5. 对一条边界执行自然化；
6. 给各省命名并填写人口；
7. 自动配色并显示名称；
8. 保存工程；
9. 导出一张 3000 px 宽的 PNG；
10. 关闭并重新打开工程后，所有几何、层级、属性和样式保持一致。

# 3. 技术栈与架构约束

## 3.1 基础环境

| 项目 | 要求 |
|---|---|
| Python | 3.12 或更高的 3.x 版本 |
| GUI | PyQt6 |
| 图形场景 | `QGraphicsView` + `QGraphicsScene`，或经验证能满足同等交互的自定义 QWidget 画布 |
| 几何运算 | 优先使用 Shapely 2.x |
| 数值计算 | NumPy |
| 图像导出 | Qt 绘制体系，必要时使用 Pillow |
| 测试 | pytest、pytest-qt |
| 打包 | PyInstaller |
| 数据校验 | dataclasses + 显式校验，或 Pydantic 2.x |

## 3.2 架构分层

必须至少分成以下层，不得把主要业务逻辑全部堆进 `MainWindow`：

```text
atlasweave/

  commands/

  ui/
    main_window.py
    welcome_window.py
    canvas/
    docks/
    dialogs/
    models/
    widgets/
    resources/

```

## 3.3 分层职责

| 层 | 职责 | 禁止事项 |
|---|---|---|
| Domain | 工程、区域、层级、共享边界、属性等纯数据与规则 | 不得依赖 PyQt 控件 |
| Services | 几何运算、导出、自然化、保存等用例 | 不得直接操作具体 UI 控件 |
| Commands | 可撤销操作及其前后状态 | 不得包含不可重现的隐式随机数 |
| UI | 呈现、事件转译、对话框、交互反馈 | 不得自行修改 Domain 绕过命令系统 |
| IO | 文件读写、迁移、备份 | 不得静默吞掉损坏错误 |

## 3.4 坐标系统

1. 工程使用二维笛卡尔世界坐标。
2. 世界原点 `(0, 0)` 位于地图矩形左下角。
3. X 轴向右，Y 轴向上。
4. 默认单位为 km。
5. 所有工程几何必须存储为世界坐标，不得存储屏幕像素坐标。
6. 内部浮点使用 Python `float`（双精度）。
7. JSON 序列化时最多保留 8 位小数，但不得因格式化造成可见几何漂移。
8. Qt 场景若采用 Y 向下坐标，应由唯一的坐标转换层负责翻转，业务层仍保持 Y 向上。

## 3.5 标识符

- 工程、层级、区域、环、共享边、顶点、样式预设必须使用 UUID v4 字符串作为稳定 ID。
- 名称可以重复时不得作为引用键。
- 删除并撤销后，应恢复原 UUID。
- 另存为不得重建对象 UUID。

## 3.6 随机算法可重现

边界自然化涉及随机扰动时：

1. 每次操作生成并记录 `seed`；
2. 命令对象保存参数与 seed；
3. 重做必须得到与首次执行完全相同的顶点序列；
4. 工程保存的是最终几何，不要求打开时重新计算；
5. 对话框提供“换一个结果”时，每次生成新 seed，但仅最终确认结果进入撤销栈。

## 4.2 HierarchyLevel

每个行政层级定义：

| 字段 | 类型 | 规则 |
|---|---|---|
| `id` | UUID | 稳定 ID |
| `order` | int | 从 0 开始连续排序 |
| `name` | string | 如“国家级”“省级”“地市级” |
| `default_type_name` | string | 如“国家”“省”“市” |
| `boundary_style_key` | string | 对应边界视觉级别 |
| `label_style_key` | string | 对应标签视觉级别 |
| `enabled` | bool | 是否在当前工程启用 |

规则：

1. 工程必须至少有一个层级。
2. 0 级称为顶级层级，可以存在一个或多个顶级区域，以支持多个国家或离散世界。
3. 除 0 级区域外，每个区域必须有且仅有一个父区域。
4. 父区域的层级必须严格高于子区域。
5. V1.0 UI 默认只允许父级为相邻上一层；高级选项可允许跨级，但默认关闭。
6. 删除包含区域的层级前必须处理其区域，不得直接造成悬空对象。

## 4.4 多部件区域与飞地

1. 一个区域可以由多个互不相连的面组成。
2. 最大面积的面称为主体，仅用于标签和 UI 排序，不改变法律意义。
3. 小面可以是岛屿、飞地或离散领土。
4. 多部件区域在树中只显示一个区域节点。
5. 选择区域时，所有部件同时高亮。
6. 几何编辑时可选择“整个区域”或其中一个部件。
7. 自动标签默认放在视觉上最适合的面内，通常是主体；用户可手动移到其他部件。

## 4.6 拓扑模型

### 核心原则

**相邻区域之间的公共边界必须是同一份几何数据，而不是两条位置相近的独立线。**

推荐使用半边结构（Half-edge）或等价的拓扑图：

- `Vertex`：唯一坐标点；
- `Edge`：两个顶点之间的边，可包含中间采样点或曲线定义；
- `HalfEdge`：带方向的边引用；
- `Ring`：有序半边序列；
- `Face`：一个外环和零个或多个内环；
- `Region`：引用一个或多个 Face。

### 边界编辑规则

1. 移动共享边界时，两侧区域必须同步变化。
2. 边界两端的拓扑节点不能被无意断开。
3. 三个及以上区域交汇的节点是“多区域结点”，移动时所有关联边保持连接。
4. 删除共享边意味着合并相邻面，不得只让一侧消失。
5. 区域边界与父区域外边界重合时，应引用或严格约束到同一几何。
6. 存盘前必须执行拓扑一致性校验。

## 4.7 几何合法性

有效区域必须满足：

- 外环闭合；
- 每个环至少 3 个不同顶点；
- 面积大于工程容差；
- 无自相交；
- 洞完全位于外环内部；
- 同一父级下的有效兄弟区域不得面积重叠；
- 子区域不得超出父区域；
- 共享边两侧坐标一致；
- 不得存在 NaN、Infinity；
- 不得出现长度近似为 0 的边；
- 环方向在规范化后统一：外环逆时针、内环顺时针。

工程容差建议：

```text
coordinate_epsilon = max(world_width_km, world_height_km) * 1e-9
minimum_edge_length = max(world_width_km, world_height_km) * 1e-6
minimum_face_area = world_width_km * world_height_km * 1e-10
```

UI 吸附容差使用屏幕像素定义，再转换为世界单位，不得直接固定为 km。

# 5. 应用启动与窗口生命周期

## 5.1 启动顺序

1. 创建日志目录；
2. 加载应用设置；
3. 检查上次会话是否异常终止；
4. 检查是否存在更新后的自动保存文件；
5. 若有可恢复内容，先显示“恢复未保存工程”对话框；
6. 否则根据设置显示欢迎页或打开最近工程；
7. 初始化主窗口；
8. 异步加载非关键资源；
9. 状态栏显示“就绪”。

## 5.2 单实例与多窗口

V1.0 采用：

## 15.3 编辑提交逻辑

## 15.4 多选状态

- 行政类型；
- 可见性；
- 锁定；
- 填充颜色；
- 部分自定义字段。

不同值显示“多个值”。

批量修改：

- 作为一个撤销命令；
- 若某些对象因锁定或字段不适用无法修改，应先显示影响摘要；
- 不得静默跳过失败对象。

# 18. 创建顶级区域

## 18.1 启动方式

- 工具栏“绘制区域”；
- 菜单“区划 > 绘制顶级区域”；
- 新建工程向导完成后自动进入。

若当前层级不是 0 级且没有选中父区域，点击绘制区域时弹出小型选择菜单：

- 在当前层级创建；
- 创建顶级区域；
- 取消。

## 18.2 多边形点击绘制

1. 首次单击创建起点；
2. 移动鼠标显示到当前点的虚线预览；
3. 后续单击添加顶点；
4. 双击、按 Enter 或点击起点闭合；
5. 至少 3 个有效顶点；
6. Backspace 删除最后一个未确认顶点；
7. Esc 第一次取消当前线段，第二次放弃整个草稿；若无子状态则一次放弃；
8. 绘制时可平移和缩放，草稿保持；
9. 不能在世界矩形外落点；
10. 若闭合后自交，保持草稿并标红问题段，不创建区域。

## 18.3 Shift 约束

按住 Shift 时，当前线段相对上一顶点吸附到：

- 0°；
- 45°；
- 90°；
- 135°；

角度容差为 7°。

## 18.4 创建完成对话框

闭合成功后，在右侧属性面板进入“新区域”临时编辑状态，不弹出阻塞式大对话框。

必须填写：

- 名称；
- 层级；
- 行政类型。

可选：

- 上级；
- 颜色；
- 其他属性。

底部操作：

- “创建区域”；
- “继续绘制同级区域”复选框，默认开启；
- “放弃”。

在确认前区域以半透明主色显示。

## 18.5 与现有区域关系

顶级区域默认允许彼此不相连，但不得重叠。

若新轮廓与现有同级区域重叠：

- 标红重叠区；
- 禁止确认；
- 提供“裁掉与现有区域重叠部分”；
- 提供“改用切分工具”的说明；
- 不得自动覆盖已有区域。

# 19. 在父区域内创建子区域

## 19.1 两种创建策略

### 策略 A：切分式建区

推荐且默认。用户选择一个尚未完全划分或已有区域，然后用切分线把它拆成两个兄弟区域。

优点：

- 自动共享边界；
- 不产生缝隙；
- 适合连续覆盖式行政区。

### 策略 B：封闭轮廓建区

用户在父区域内画完整闭合多边形。

适合：

- 自治区域；
- 不要求完全覆盖父区域的下级；
- 岛屿或飞地；
- 先局部设计。

## 19.2 覆盖模式

每个层级对某个父区域可处于：

- **完全覆盖模式**：所有有效子区域理论上应完整覆盖父区域；
- **部分覆盖模式**：允许存在未分配空间。

V1.0 默认“部分覆盖模式”，但提供“检查覆盖完整性”。

工程设置可将某层级默认设为完全覆盖。完全覆盖下：

- 空隙作为问题列出；
- 不强制阻塞保存；
- 导出前可选择是否阻止。

## 19.3 父级裁剪

封闭轮廓超出父区域时：

- 超出部分红色斜线覆盖；
- 确认按钮禁用；
- 提供“裁剪到父区域”按钮；
- 裁剪后若产生多个部件，应在确认前告知；
- 裁剪后面积过小的碎片按容差剔除，并在摘要中说明。

# 20. 切分区域工具

## 20.1 前置条件

- 必须且只能选中一个有效区域或一个具体面部件；
- 区域未锁定；
- 用户拥有几何编辑权限（V1 本地均有）；
- 若区域有子区域，默认禁止直接切分父级，除非选择“仅切分父级轮廓并重新校验子区”高级操作。

## 20.2 绘制切分线

切分线为开放折线：

1. 在区域外或边界上开始；
2. 逐点绘制；
3. 在区域外或边界上结束；
4. Enter 或双击完成；
5. 切分线必须与目标区域边界产生恰好两个有效穿越点，简单凹多边形可有更多交点时进入选择步骤；
6. 不足两个交点则提示“切分线没有完整穿过区域”；
7. 切分结果少于两个有效面则失败；
8. 切分线可以是直线、折线或自由手绘线。

## 20.3 多交点处理

若切分线穿过凹形区域多次：

- 预览所有候选结果；
- 默认选择沿整条切分线产生的全部合法拆分；
- 若产生 3 个以上面，弹出结果摘要；
- 用户可确认创建多个区域，或取消后重画；
- V1 不要求交互式选择某两个交点。

## 20.4 结果命名

切分后原区域处理方式：

默认：

- 面积最大的结果保留原区域 UUID、名称和属性；
- 其他结果创建新区域；
- 新区域名称依次为“{原名称} - 新区域 1”等；
- 属性面板立即进入批量命名模式。

可在确认条中切换：

- “两个结果都作为新区域，删除原区域”；
- “较大区域保留原对象”（默认）。

## 20.5 切分边界

- 新切分线生成一组共享边；
- 两侧面引用相反方向的半边；
- 线与原边界交点必须插入为共享顶点；
- 原边界被交点拆分后，所有引用它的相邻面同步更新；
- 操作整体是一个撤销命令。

## 20.6 预览与确认

完成切分线后：

- 结果面以两种临时颜色显示；
- 新共享边使用主色粗线；
- 顶部画布内确认条显示：
  - 结果区域数；
  - 最小区域面积；
  - 确认；
  - 重新绘制；
  - 取消。

确认后才修改正式模型。

# 21. 自由手绘

## 21.1 用途

- 绘制国土轮廓；
- 绘制封闭子区域；
- 绘制切分线；
- 绘制自然弯曲的边界草稿。

## 21.2 采样

- 鼠标按下开始；
- 移动时按屏幕距离采样，默认每 4 px 至少一个点；
- 速度过快时用事件插值避免大缺口；
- 松开完成；
- 闭合区域模式下，若终点距起点小于 14 px 自动闭合；
- 否则显示“闭合轮廓”与“继续绘制”选择。

## 21.3 自动简化

手绘结束后先做非破坏性简化预览：

- 默认目标误差 1.5 屏幕像素转换后的世界距离；
- 保留明显转角；
- 不改变拓扑节点；
- 不允许因简化产生自交；
- 用户可在确认条用“细节”滑块调整 0–100；
- 原始采样点仅在当前操作确认前保留；
- 确认后保存简化结果。

# 22. 顶点与边界编辑

## 22.1 进入顶点模式

- 选择一个区域后按 `V`；
- 或点击“编辑顶点”；
- 若多选区域，仅显示共享外轮廓的可编辑节点；无法确定时提示先选择一个区域。

显示：

- 普通顶点：白色填充、灰色描边，直径 8 px；
- 选中顶点：主色填充，直径 10 px；
- 多区域结点：菱形，直径 11 px；
- 曲线控制信息使用橙色；
- 当前边悬停加粗。

手柄大小保持屏幕恒定，不随缩放变化。

## 22.2 顶点选择

- 单击顶点；
- Ctrl 多选；
- 拖框选择；
- 单击空白取消顶点选择但保留区域选择；
- Tab 在当前环的顶点间循环；
- Shift+Tab 反向循环。

## 22.3 移动顶点

- 左键拖动；
- 实时显示新边界预览；
- 默认开启吸附；
- 按 X 临时禁用吸附；
- 按 Shift 限制水平或垂直，以位移主方向为准；
- 拖动中若产生自交，预览变红；
- 松开时若无效，顶点回到原位并显示原因；
- 拖动共享顶点时所有关联边同步；
- 一次连续拖动为一个撤销命令。

## 22.4 插入顶点

方式：

- 双击边界；
- 选中边后按 Insert；
- 右键“在此插入顶点”。

规则：

- 新点投影到边的实际几何；
- 若是曲线段，插入后视觉曲线应尽可能不变；
- 新顶点插入共享边后，两侧区域同步；
- 距已有顶点小于 8 px 时不插入，改为选择已有顶点。

## 22.5 删除顶点

- 选中后 Delete；
- 删除前实时预览合并后的边；
- 环不得少于 3 个不同顶点；
- 删除多区域结点默认禁止；
- 删除会产生自交、零面积或越界时禁止；
- 删除共享边内部普通顶点会同步两侧；
- 一次删除多个顶点为一个撤销命令。

## 22.6 移动整段边界

选中一条非闭合共享边链后，可拖动整段：

- 边链内部采样点整体移动；
- 两端拓扑结点默认固定；
- 采用平滑衰减连接移动部分与固定端点；
- 按 Alt 可连同两端结点一起移动；
- 预览必须实时检查两侧区域合法性。

## 22.7 曲线表示

V1.0 工程中的最终面几何仍以折线采样点参与拓扑和导出。

为了可编辑性，边可以附带：

- `segment_mode`: `polyline` 或 `smooth`;
- 控制点；
- 拟合参数；
- 用于渲染和重新采样。

任何曲线在几何布尔运算前必须按容差采样为折线。导出 SVG 时可以保留贝塞尔曲线，但 GeoJSON 必须输出折线坐标。

# 24. 边界自然化

## 24.1 功能目的

将用户绘制的过于笔直、机械或规则的边界，转换为具有真实行政边界观感的不规则线，同时：

- 保持两端节点；
- 保持共享拓扑；
- 不产生自交；
- 不穿出允许区域；
- 不制造不可见微小锯齿；
- 用户可控制强度与风格；
- 结果可复现、可撤销。

## 24.2 可操作对象

- 一条选中边；
- 多条连续边组成的边链；
- 一个区域的全部外边界；
- 多选区域之间的共享边界集合。

默认只自然化选中边链，不自动处理整个区域。

禁止条件：

- 对象锁定；
- 边太短，无法在当前参数下生成至少 3 个采样段；
- 操作会改变父级外边界但父级锁定；
- 当前几何已无效且无法建立安全缓冲区。

## 24.3 对话框

非模态或模态均可，但必须实时预览。推荐右侧临时面板。

字段：

| 参数 | 范围 | 默认 | 说明 |
|---|---:|---:|---|
| 风格 | 枚举 | 历史边界 | 历史边界、河流感、山脊感、人工勘界、海岸感 |
| 不规则强度 | 0–100 | 35 | 最大横向偏移 |
| 细节尺度 | 0–100 | 45 | 大弯与小弯比例 |
| 平滑度 | 0–100 | 55 | 抑制尖刺 |
| 节点密度 | 0–100 | 40 | 输出采样点数量 |
| 保持原方向 | 复选 | 开 | 防止整体严重偏离 |
| 保护端点附近 | 0–30% | 10% | 两端扰动衰减范围 |
| 随机种子 | 整数/自动 | 自动 | 可重现 |

按钮：

- 换一个结果；
- 重置参数；
- 应用；
- 取消。

## 24.4 风格语义

### 历史边界

- 多尺度缓慢弯折；
- 少量局部折转；
- 不呈明显周期波浪；
- 默认通用风格。

### 河流感

- 连续蜿蜒；
- 曲率平滑；
- 弯道大小不一；
- 不出现尖锐折角。

### 山脊感

- 总体方向稳定；
- 局部有连续偏转；
- 比河流感更不对称；
- 可有少量较明显折点。

### 人工勘界

- 以较长直段为主；
- 偶尔改变方向；
- 强度默认较低；
- 不生成细碎抖动。

### 海岸感

- 多尺度细节最多；
- 可形成小湾和凸角；
- V1 仍不得生成新的岛屿或洞；
- 对行政内陆边界使用时给出提示但允许。

## 24.5 推荐算法约束

可采用以下组合：

1. 按弧长重采样基线；
2. 构造局部切线与法线；
3. 使用固定 seed 的分形噪声或多频带平滑随机场；
4. 沿法线偏移；
5. 端点区域用平滑窗衰减到 0；
6. 低通平滑；
7. 约束到合法缓冲区；
8. 检测自交及与非目标边界冲突；
9. 必要时降低振幅重试；
10. 简化冗余点。

不得简单地对每个点独立随机抖动，因为会形成锯齿。

## 24.6 强度换算

强度必须相对边长度和局部可用空间计算，不得固定使用某个 km 值。

建议：

```text
base_amplitude = edge_chain_length * lerp(0.001, 0.06, intensity / 100)
actual_amplitude = min(base_amplitude, legal_clearance * 0.45)
```

界面可在滑块旁显示估算最大偏移，例如“约 8.4 km”。

## 24.7 失败处理

若在 8 次自动降低振幅后仍无法得到合法结果：

- 不修改模型；
- 显示“当前边界周围空间过窄，无法按此强度生成合法结果”；
- 提供“降低强度到建议值”；
- 不得应用无效几何。

# 25. 平滑与简化

## 25.1 平滑

参数：

- 强度 0–100；
- 迭代次数 1–10；
- 保持端点；
- 保持面积；
- 保护拓扑结点。

规则：

- 使用拓扑保持型简化；
- 不得分别简化共享边两侧；
- 不得删除多区域结点；
- 不得导致子区域越出父级；
- 确认前显示最大视觉偏差。

# 26. 区域合并

## 26.1 条件

- 至少选择两个同层级区域；
- 父级相同；
- 区域未锁定；
- 可以相邻，也可以不相邻；

## 26.2 属性处理对话框

- 新名称；
- 新行政类型；
- 人口：求和/保留主区域/留空；
- GDP：求和/保留主区域/留空；
- 文本字段：选择主区域或手动；

## 26.3 几何

- 不相邻区域：保留多个面部件；
- 洞与飞地按几何联合结果处理；
- 主对象 UUID 保留；
- 被合并对象删除但可撤销；
- 邻接缓存重算。

# 27. 区域删除

## 27.1 删除类型

删除对话框必须根据上下文提供不同选项。

### 有子区域

- 仅删除该区域，将直接子区域提升到其父级（仅层级规则允许时）；

- 超过 20 个区域时要求输入工程名确认；
- 删除作为一个可撤销命令；
- 不移动到操作系统回收站，因为对象在工程内部；
- 删除后自动选择合理邻近对象或父区域。

# 31. 几何校验与问题面板

## 31.1 校验时机

- 完成绘制时；
- 顶点拖动松开时；
- 切分、合并、删除后；
- 修改父级后；
- 保存前执行轻量校验；
- 用户执行“校验整个工程”时执行完整校验；
- 导出前检查与当前导出有关的问题。

## 31.2 问题级别

| 级别 | 含义 | 是否阻止保存 | 是否阻止导出 |
|---|---|---|---|
| 错误 | 数据或几何无效 | 否，允许保存以便修复 | 默认阻止 |
| 警告 | 可能不合理但可接受 | 否 | 否 |
| 信息 | 建议或非关键状态 | 否 | 否 |

## 31.3 必检问题

错误：

- 自相交；
- 面积为零或过小；
- 子区域越出父级；
- 同父同层兄弟重叠；
- 共享边不一致；
- 环未闭合；
- 引用不存在对象；
- 父子循环；
- 无效数值；
- 重复 UUID。

警告：

- 完全覆盖模式存在空隙；
- 区域无名称；
- 同一父级下名称重复；
- 标签无法放置；
- 极短边；
- 极小碎片；
- 多部件区域；
- 区域没有父级但不是顶级；
- 人口或 GDP 为负值（输入阶段应已阻止，导入时可能出现）。

## 31.4 问题面板列

- 级别；
- 对象；
- 问题；
- 建议；
- 修复状态。

交互：

- 双击问题定位并选中对象；
- 右键“缩放到问题”“自动修复”“忽略此警告”；
- 错误不可忽略；
- 忽略警告记录其问题类型和对象 ID；
- 几何变化后重新评估已忽略项。

## 31.5 自动修复

V1.0 可以自动修复：

- 移除连续重复点；
- 闭合首尾非常接近的环；
- 删除极短悬挂段；
- 统一环方向；
- 将近距离端点吸附；
- 使用 `make_valid` 产生候选结果。

任何可能改变区域部件数或面积超过 0.5% 的修复必须预览并确认。

# 32. 撤销与重做

## 32.1 技术要求

- 使用 `QUndoStack` 或功能等价的命令系统；
- 所有模型修改必须由命令执行；
- 命令必须实现 redo/undo；
- 保存点使用 clean index；
- 窗口标题未保存标记由撤销栈 clean 状态驱动，同时考虑非撤销型元数据变化。

## 32.2 可撤销操作

- 创建、删除、复制、粘贴区域；
- 切分、合并；
- 顶点移动、插入、删除；
- 自然化、平滑、简化；
- 修改属性；
- 修改父级或层级；
- 自动配色；
- 手动颜色；
- 标签位置；
- 图例和标题设置；
- 自动修复。

## 32.3 不进入撤销栈

- 选择；
- 缩放和平移；
- 面板开关；
- 表格排序和筛选；
- 保存；
- 导出；
- 打开问题定位；
- 临时预览。

## 32.4 命令合并

应合并：

- 同一顶点的一次连续拖动；
- 同一文本字段连续输入；
- 同一滑块一次按下到松开；
- 同一标签一次拖动。

不得合并：

- 两次独立自然化；
- 不同对象属性修改；
- 用户已执行其他操作后的修改。

## 32.5 撤销历史限制

- 默认最多 500 个命令；
- 大型几何命令按内存估算，可动态减少；
- 不允许因历史限制删除保存点之后所有记录而错误显示已保存；
- 工程关闭时不保存撤销历史。

# 33. 工程文件格式

## 33.1 扩展名

工程文件扩展名：

```text
.atlasweave
```

文件本质为 ZIP 容器，至少包含：

```text
project.json
topology.json
styles.json
thumbnail.png
```

可选：

```text
extensions/
attachments/
```

## 33.2 为什么使用容器

- 避免单个巨大 JSON；
- 便于未来加入缩略图和附件；
- 便于版本迁移；
- 可原子替换整个工程文件；
- 用户不应手工依赖内部结构，但格式需有文档。

## 33.3 保存流程

1. 在内存中执行轻量校验；
2. 序列化到同目录临时文件；
3. 写入完成后重新打开并验证 ZIP 与 JSON；
4. 若目标存在，将旧文件轮换为 `.bak`；
5. 使用原子替换写入目标；
6. 成功后删除过期临时文件；
7. 更新撤销栈 clean 状态；
8. 更新最近工程。

不得直接在原文件上原位覆盖。

## 33.4 备份

- 保留最近 3 个手动保存备份；
- 文件名可为 `.atlasweave.bak1` 等；
- 首选项允许 0–10；
- 备份失败不应让主保存失败，但必须记录日志并提示。

## 33.5 格式版本

- 使用语义版本字符串；
- 读取低版本时通过迁移器升级到内存模型；
- 保存后写当前版本；
- 读取高于应用支持版本的工程时：
  - 默认只读打开；
  - 明确提示可能不兼容；
  - 禁止覆盖原文件；
  - 允许“另存为兼容副本”仅在不会丢数据时提供。

## 33.6 未知字段

- 解析时保留未知顶级扩展字段；
- 保存时原样写回；
- 若某未知字段位于无法安全保留的内部结构中，必须警告；
- 不得静默删除未来版本数据。

- 是否显示父级边界；
- 是否显示标签；
- 是否显示标题；
- 是否显示图例；
- 是否显示背景；
- 是否包含隐藏区域，默认否。

## 36.3 画面

位图：

- 宽度 px；
- 高度 px；
- 锁定长宽比；
- DPI；
- 边距；
- 背景透明。

默认：

- 3000 × 按比例计算 px；
- 150 DPI；
- 边距 40 px。

限制：

- 任一边 256–30000 px；
- 预计内存超过 1 GB 时警告；
- 超过安全阈值时使用分块渲染或拒绝并建议降低尺寸。

## 36.4 格式

### PNG

- RGBA；
- 支持透明；
- 文字抗锯齿；
- 嵌入 DPI。

### SVG

- 区域为矢量路径；
- 文本优先保持文本；
- 提供“将文字转路径”选项可以预留，V1 非必须；
- 共享边界避免重复绘制；
- 正确设置 viewBox。

### PDF

- 矢量优先；
- 页面尺寸可选 A4/A3/自定义；
- 横向/纵向；
- 适合打印；
- 字体嵌入由 Qt 能力决定，失败时记录警告。

## 36.5 预览

- 预览应真实反映标签、图例、标题和裁剪；
- 参数变化后 300 ms 防抖刷新；
- 大工程先低分辨率预览；
- 预览支持缩放；
- 预览错误不得影响正式模型。

## 36.6 文件命名

若文件存在：

- 替换；

规则：

- 坐标单位 km；

# 47. 数据一致性规则

任何命令提交后必须满足：

1. 所有区域引用存在的层级；
2. 所有非顶级区域引用存在的父区域；
3. 父子关系无循环；
4. 所有 Face 引用存在的 Ring；
5. 所有 Ring 引用存在的 HalfEdge；
6. 所有 HalfEdge 引用存在的 Edge 和 Vertex；
7. 共享 Edge 的两条 HalfEdge 方向相反；
8. 删除对象无悬空引用；
9. 邻接关系可从拓扑重建；
10. 面积和包围盒缓存与几何版本一致。

开发模式下每个命令后可以运行断言；发布模式下对高风险命令运行轻量校验。

# 附录 C：未来地形模块接口原则

V1.0 不实现地形，但未来地形加入时必须能够：

1. 使用与当前世界相同的坐标系统；
2. 提供高程栅格；
3. 从高程推导坡度、汇流和河网；
4. 让边界自然化选择“沿山脊”“沿河流”约束；
5. 校验行政边界与地形关系；
6. 不破坏既有行政工程；
7. 将当前纯行政地图升级为地形世界，而无需重新绘制全部区域。

因此 V1 的拓扑边允许预留：

```json
{
  "constraint_type": null,
  "constraint_feature_id": null
}
```

未来可取值：

- `river`;
- `ridge`;
- `coastline`;
- `road`;
- `latitude`;
- `custom`.

# 附录 D：产品原则

1. **创作自由优先，但永远告诉用户哪里不合理。**
2. **共享边界是真实数据，不是两条看起来重合的线。**
3. **系统可以建议，最终决定属于用户。**
4. **每个重要操作都应可预览、可撤销、可恢复。**
5. **第一版先成为最好用的行政区划编辑器，再向世界模拟器生长。**
